1. Executive Summary & Project Overview

TypeBaazi is a modern, high-performance, gamified typing speed platform designed to solve the critical gap in dual-language typing education—specifically tailored for English and Standard Unicode Marathi (Devanagari).

Unlike traditional platforms that cater only to English or rely on obsolete font hacks (e.g. Kruti Dev / Shree Lipi) that fail in modern government exams, TypeBaazi is engineered from the ground up for modern Unicode standards (Marathi InScript and Marathi Remington layouts) utilized in competitive government exams like MPSC, SSC CGL, Court Steno, Talathi, and Railway RRB.

🎯 Key Project Achievements:
  • 25 Dedicated SEO Landing Pages: High-intent keyword targeting with 100% structured JSON-LD schemas and 0 console errors.
  • Guest-First Architecture: Zero-friction entry. Users can practice, race AI bots, and track daily streaks immediately without being forced to create an account.
  • Web Crypto Security: SHA-256 hashed password verification with seamless client-side guest history migration.
  • Universal Platform: Web App + Offline Progressive Web App (PWA) + Native Android APK (built via Capacitor).
  • Zero-Asset Sound Engine: Real-time mechanical switch sound synthesis via Web Audio API with zero network latency.

3. Step-by-Step Implementation Journey

Step 1: Core Dual-Language Typing Engine & Unicode Grapheme Parser

Built src/lib/typingEngine.ts and src/lib/textGenerator.ts. Standard JavaScript strings measure character length naively, which breaks Devanagari conjuncts (e.g. क् + ष = क्ष or matras ा, ि, ी, ु, ू). We implemented a specialized grapheme cluster tokenizer so that Marathi characters are typed and scored accurately with precise word boundary detection.

Step 2: Cyberpunk Typing Arena & Virtual Interactive Keyboard

Created TypingArena.astro and VirtualKeyboard.astro. Renders active finger guidance, dynamic keypress ripples, and on-the-fly switching between:

4. Interview Preparation: High-Yield Technical Q&A

Q1: Why did you choose Astro over Next.js or React SPA for TypeBaazi?
Answer: Next.js and typical React SPAs ship heavy JavaScript bundles by default, which harms Core Web Vitals (especially First Input Delay and Largest Contentful Paint on mobile devices). Astro's Islands Architecture allows us to ship 0KB JavaScript for content pages while selectively hydrating dynamic islands (the typing engine and race track) with client:load. This resulted in perfect 100 Lighthouse performance scores and faster SEO indexing on Google.
Q2: How does TypeBaazi accurately calculate WPM and Net WPM?
Answer: In standardized typing metrics, 1 word is defined as 5 keystrokes (including spaces).
• Gross WPM: (Total Characters Typed / 5) / (Time Elapsed in Minutes)
• Net WPM: Gross WPM - (Uncorrected Errors / Time Elapsed in Minutes)
• Accuracy: ((Total Characters - Errors) / Total Characters) * 100
Q3: How did you solve Devanagari / Marathi typing accuracy compared to English?
Answer: English characters have a 1:1 mapping with UTF-16 code units. Devanagari characters consist of base consonants combined with viramas (halant) and matras to form conjuncts (ligatures). We utilized Unicode normalization (NFC/NFD) and regex cluster matching to treat conjuncts as atomic units, ensuring users are not penalized for complex glyph rendering differences across operating systems.
Q4: How does the Guest-First architecture work with LocalStorage and Cloud Auth?
Answer: To reduce friction and maximize user acquisition, TypeBaazi operates 100% in Guest Mode upon first visit. Stats, streaks, and history are stored in localStorage under versioned keys. When the user creates an account, the frontend computes a SHA-256 hash using the native crypto.subtle API, registers the account, and automatically transfers their guest dataset into their new account record without losing a single day of practice streak.
Q5: How did you implement real-time AI bot opponents without a heavy backend?
Answer: Rather than relying on constant WebSocket roundtrips which introduce latency and server costs, we built an event-driven bot engine (raceEngine.ts). Each bot runs a client-side stochastic algorithm that calculates progress ticks based on target WPM, jitter, simulated typo frequencies, and recovery pauses. This delivers a responsive, zero-lag 60fps multiplayer racing experience directly on the client.
Q6: How did you ensure responsive UI stability and prevent modal content clipping?
Answer: We implemented a flexbox container layout with strict viewport bounding (max-height: min(90vh, 90dvh)). The header and status alerts are assigned flex-shrink: 0 to remain anchored, while the dynamic content is contained within an inner scroll container (overflow-y: auto). This guarantees that action buttons (Sign Out, Save Progress) never overflow or get pushed off-screen.
